# Argyle Labs

Local-first homelab & developer tooling, built around **[orca](https://github.com/argyle-labs/orca)** — a composable tool for unified communication over REST, MCP, and CLI that manages a fleet of machines from a single pane of glass, with capabilities (services, storage, containers, models, agents, and more) shipped as composable **orca plugins**.

## orca

[**orca**](https://github.com/argyle-labs/orca) — the core. One Rust binary per host that exposes a single tool surface across CLI, TUI, REST, and MCP to manage a fleet of machines from a single pane of glass. It owns the domain model (containers, storage, namespaces, pods, notifications, models, agents) and its functionality is augmented by composable, out-of-process plugins (dynamic subprocess model). The web UI is itself a plugin (peacock). Local models run by default; Claude is escalation-only.

Every plugin registers with orca through one generic surface — `service.*` (`list`, `deploy`, `backup`, `restore`, `configure`, `status`) — with rich, plugin-specific data returned in the typed `service.status` payload. Each repo below is also a **standalone setup guide**: you can deploy and operate the underlying service by hand, without orca.

## Developing a plugin

Each plugin is its own repo: an out-of-process subprocess whose only orca dependency is `plugin-toolkit`, declaring its index metadata in `Cargo.toml` (`description` + `[package.metadata.orca].category`). See the [orca plugin authoring guide](https://github.com/argyle-labs/orca/blob/main/docs/plugin-authoring.md), and [docker](https://github.com/argyle-labs/docker) or [unraid](https://github.com/argyle-labs/unraid) as worked references.
